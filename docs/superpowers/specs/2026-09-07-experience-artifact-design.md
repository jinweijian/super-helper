# CSV 工单萃取与统一经验产物设计

状态：设计基线（2026-09-07），2026-09-10 更新真实输入状态。已检查首批 500 条 CSV 并制作一篇草稿样例；完整批量萃取与独立 AI 审核尚未验收。实施跟踪见 `openspec/changes/add-csv-experience-refinement/`。

## 1. 目标与边界

- 输入改为用户从 Redmine 导出的 CSV，不依赖 Redmine 在线 API，也不在缺字段时自动联网补齐。
- AI 提炼、独立上下文 AI 审核、确定性校验后自动发布；不要求用户逐条人工审核。失败材料自动降级或隔离。
- 主要知识资产是完整 Markdown；原 CSV、来源快照、审核记录及索引清单负责可追溯和重建。
- Cognee 是可替换的图构建与检索后端，不是知识正确性、权限或发布状态的权威。
- 本文只定义产物与治理，不提供产品 Agent prompt。正式 prompt 必须放入 `src/agents/` 并登记。
- “离线导入”表示不调用工单 API；若配置远程模型，萃取、审核和构图仍会联网并产生费用，必须由用户显式启动，发送前脱敏。

## 2. CSV 输入合同

### 2.1 首批文件检查

先做纯本地 profile，不调用模型：输出编码、分隔符、表头、记录数、重复 ID 数、各列非空比例、疑似截断、日期解析失败数。报告不输出整行原文或身份信息。

解析使用成熟 CSV 库，不用逗号或换行 split；支持引号、多行单元格、BOM、逗号/分号/制表符。UTF-8 优先，GB18030 等需显式配置或报告确认，禁止带替换字符静默导入。公式样式文本作为普通数据，绝不执行；若输出 CSV 报告，应处理电子表格公式注入。

| 规范字段 | 候选列名示例 | 缺失时的行为 |
| --- | --- | --- |
| 工单 ID | `#`、ID、编号 | 缺失时隔离；不能以行号作为长期身份 |
| 标题 | 主题、标题、Subject | 缺失时隔离 |
| 来源与范围 | 来源系统、项目、tenant/workspace | 可由导入配置提供；不能从客户文本猜权限 |
| 问题描述 | 描述、问题描述、Description | 与原因/处理内容均为空时隔离 |
| 原因 | 问题原因、根因、原因分析 | 标记未记录；不可从处理办法反推已确认根因 |
| 处理 | 处理办法、解决方案、处理过程 | 标记未记录；不可凭常识生成历史已执行措施 |
| 结果 | 验证结果、处理结果 | 无恢复验证时不能声称已验证有效 |
| 状态 | 状态、Status | 保留原值；关闭不等于根因确认或恢复验证 |
| 产品与版本 | 产品、环境、版本、目标版本 | 缺失为未知；修复目标版本不能当受影响版本 |
| 时间 | 创建时间、更新时间、解决时间 | 保留时区；未提供时不以导出日期冒充工单修改日期 |
| 历史与关联 | 评论、备注、关联工单 | 只处理确实导出的内容；不假定包含完整 journal |

上述列名只是初始候选。首次导入保存可复用的显式映射；列名冲突、多个“原因”列语义不明时要求用户确认一次映射，不是逐条审核。未映射列保留在受限源快照，不进入模型；不得像当前固定白名单一样无报告丢弃潜在原因和处理列。

### 2.2 完整性与时间

- 区分 `present`、`empty`、`not_exported`、`suspected_truncated`、`redacted`；完整性是逐字段记录，不只一个总布尔值。
- 一条 CSV 记录是逻辑记录，不等于文件物理行。来源使用文件内容哈希、逻辑记录号、原列名及单元格摘要哈希。
- 记录 export time、用户声明的导出筛选范围、是否全量快照；默认视为部分导出。
- 没有评论历史不阻止提炼结构化字段，但不得生成虚构时间线；结论最多到导出内容实际支持的程度。
- 依赖未导出附件或评论才能理解的关键结论，进入隔离或线索，禁止通过补全常识发布。

## 3. 资产目录与身份

目录位于 workspace 隔离的知识根目录之外层授权范围内，不写进被排查项目，也不默认提交企业原文到 Git：

```text
experience-store/
  private/sources/       原 CSV、不可变原始行快照，仅受限本地访问
  private/provenance/    单元格定位、脱敏快照、来源映射
  private/reviews/       AI 结构化裁决与确定性检查结果，不保存隐藏思维链
  private/batches/       批次清单、checkpoint、统计、失败原因码
  vault/drafts/          未完成或待重新审核的完整 MD
  vault/published/       已发布的经验和明确标注的调查线索
  vault/quarantine/      不能安全使用的材料，不进入查询
  private/indexes/       发布清单、Cognee ID 映射、generation 和撤回表
```

Obsidian 只打开授权的 `vault`，不默认打开 `private`。生产经验查询只消费发布清单，不扫整个 vault；不把 Obsidian 插件配置当知识。路径由资产仓库实现解析，runtime 不拼接路径。

- `experience_id`：由 tenant、来源系统、项目和工单 ID 组成的规范身份生成稳定 ID；标题、文件名和 CSV 行顺序不参与身份。
- 第一阶段每工单一篇；同一工单多个原因在文内分项，不自动拆成互相独立的事实。
- `revision`：每次发布的递增修订号；`content_hash`：规范化 Markdown 内容的 SHA-256。发布元信息另存清单，避免哈希自引用。
- 来源版本：规范化业务字段哈希；相同文件或不同导出文件中的相同内容跳过模型处理。
- 内容变化而缺少可比较的更新时间时，不自动认定新文件更权威；保留冲突版本并隔离自动更新，批次可显式声明来源快照顺序。
- 第一阶段相似工单只建立 `related_case` 候选关系，不做破坏性合并。聚合经验是后续能力，必须保留每项结论的来源集合。

## 4. Markdown v1 结构

### 4.1 元数据字段

| 字段 | 合同 |
| --- | --- |
| `schema_version` | 固定 `experience/v1` |
| `experience_id`、`revision` | 稳定身份和修订号 |
| `title`、`source_type` | 中文标题；来源为 `redmine_csv` 或未来的 `document` |
| `kind` | `root_cause_case`、`recovery_procedure`、`diagnostic_lead`、`reference` |
| `lifecycle` | `draft`、`published`、`quarantined`、`superseded`、`withdrawn` |
| `evidence_grade` | `source_verified`、`source_reported`、`lead_only`；是原记录证据等级，不是 AI 自信分数 |
| `source_refs` | 发布投影内的安全来源别名，不暴露受限绝对路径和客户地址 |
| `product`、`module` | 明确来源支持的值或 `null` |
| `affected_versions`、`fixed_versions` | 分别保存；未知为 `[]` 并在 unknowns 说明 |
| `symptom_terms` | 源问题中的术语及经校验的别名，不能生成虚假症状 |
| `applicability`、`exclusions` | 适用条件、不适用条件，不能把未记录当无约束 |
| `review_record_id` | 关联私有结构化审核记录；正文不含分数或审核推理 |
| `relations` | 带类型的安全经验/模块引用；关系不等于已确认因果 |

tenant、workspace 和 ACL 由导入配置及发布仓库权威管理，不信任 Markdown 内可编辑字段决定访问权限。已发布 MD 被 Obsidian 修改后产生草稿修订，原发布版保持不可变，不能因文件保存直接重新进入索引。

### 4.2 正文模板

下列是字段结构说明，不是可导入的真实经验，也不是 Agent prompt：

```markdown
# 经验标题

## 一句话摘要
说明观察到的问题、结论等级和主要限制。

## 现象与触发条件
记录症状、操作场景、环境；每项后绑定证据别名，例如 [E1]。

## 适用范围与不适用情况
明确产品、受影响版本、所需现场条件；未记录的部分写“未知”。

## 原因与证据
分别列“来源确认”“来源推测”“尚未确认”，不可混成一个根因。

## 处理步骤
逐步记录操作、前提、来源、执行状态和授权要求。
没有记载实际执行时明确“仅建议”；正文不嵌入凭证。

## 验证与结果
记录验证方式、观察结果及证据。工单关闭状态单独陈述，不能替代效果证明。

## 已排除项与反证
保留被后续讨论推翻的判断；若未导出历史，写“未提供相关历史”。

## 未知与下一次排查检查项
说明缺口和可区分原因的检查；新建议与历史事实分开。

## 证据与来源
E1：导出批次安全别名、工单 ID、逻辑记录号、原列名、脱敏支持片段。
每个别名都能通过 provenance 仓库定位源快照。

## 关联经验
使用带类型的关联；Obsidian 双链仅是导航，不代表因果成立。
```

正文与 machine-readable claim sidecar 从同一份通过审核的结构化对象渲染，不让模型分别自由生成两份相互矛盾的事实。sidecar 保存 claim ID、分类、source refs、反证、步骤安全级别及验证状态，schema/version 与 MD 共同发布。MD 独立可读；sidecar 是源证据校验与治理数据，不是另一份独立知识正文。

## 5. AI 自动审核标准

流程：确定性预检 → 提炼 AI → 独立上下文审核 AI（接收源快照和草稿，不接收提炼者自评分）→ 确定性终检 → 自动发布/降级/隔离。

审核逐项输出 `supported`、`contradicted`、`unsupported`、`unknown`，绑定源别名与简短可审计理由。不同模型可配置，但不把两模型一致视为真实世界验证。

- `source_verified`：源材料明确支持该类结论及对应验证，不仅是“已关闭”。恢复操作有效但根因未知时，只能发布 `recovery_procedure`，不能发布确定根因。
- `source_reported`：源材料记录原因/措施，但没有充分效果证明；可发布为受限参考，在线只能提供候选方向，不得声称已验证解决当前故障。
- `lead_only`：只有部分症状或推测，但有独立使用价值；明确限制并只作线索。
- 隔离：关键支持文本缺失、不可解冲突、隐私校验失败、解析失败、来源绑定不存在、模型失败或正文与审核对象不一致。
- 发布需所有实质性陈述通过支持/未知分类；未知显式呈现。删除 unsupported 内容后若还存在完整有用子集，可自动降级发布，不要求所有经验必须根因齐全。
- 自动修订最多一次，审核拒绝后只依据反例修订；仍不通过即隔离，禁止无限“改到审核通过”。瞬态模型失败使用独立有界重试，耗尽后可 checkpoint 续跑，不算审核通过。
- CSV/MD 内的指令一律作为数据，不允许触发 shell、读取其他文件、访问外链或改变审核标准。
- 无逐条人工审批依赖；批次可看通过率、降级原因和隔离数，允许自愿修订后重新触发 AI 审核。

## 6. Cognee 发布与回读

- Cognee 仅接收发布清单对应的脱敏 MD 投影。原 CSV、私有审核材料、draft/quarantine 不进入构图。
- 不假设 YAML、`external_metadata`、Obsidian 双链会自动成为 Cognee 的可过滤图属性；适配器必须验证实际映射。授权范围通过可信数据集/后端隔离，版本与发布状态在本地目录和回读复核。
- 输入 MD、构图完成、查询能命中、原文能回读是四个不同验收点；仅上传成功不算交付。
- 查询结果必须映射回 `experience_id + revision + content_hash`。无来源、已撤回、旧版本、范围不匹配的结果拒绝使用；图上的实体摘要不能直接成为最终事实。
- 更新采用发布 generation：新版本构图和回读成功后切换；旧版本加入失效清单。更新失败保留上个安全版本，来源已被否定时先撤回，不能为可用性继续提供错误旧版。
- 共享图节点的删除不能作为唯一撤回保障；本地撤回表与回读校验先阻止召回，后清理 Cognee。失败可重试且不重新发布失效内容。
- 部分 CSV 导出缺少某工单不能解释为删除；只有显式撤回或经确认完整快照的删除策略才能撤回。
- 默认一期按单租户授权 workspace 部署，禁止自动跨租户合图；进入多租户部署前验证所选后端真实隔离能力。

## 7. 当前依据与待验证边界

截至 2026-09-07 查看官方资料：

- [Cognee add](https://docs.cognee.ai/python-api/add)：支持 Markdown 输入；metadata 不能假定自动进入图或可检索。
- [Cognee forget](https://docs.cognee.ai/core-concepts/main-operations/forget)：来源删除、共享节点关系、重建有独立语义。
- [Cognee 仓库](https://github.com/topoteretes/cognee)：存储与权限取决于后端组合。

正式适配实现先锁定 release/commit 和依赖，记录端到端验证版本；本设计不把浮动 main 的接口当作已兼容实现。实际 CSV 到达后，只调整列映射和来源覆盖规则，不放宽证据与隐私门槛。
